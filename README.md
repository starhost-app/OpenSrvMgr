# OpenSrvMgr

Stateless Rust node daemon for the Panel/Node gRPC protocol in `proto/node.proto`.

## Startup

All network binds are mandatory. There are no environment-variable bind fallbacks or bind defaults:

```text
OpenSrvMgr --sftp-bind 0.0.0.0:2022 --grpc-bind 0.0.0.0:50051 --panel-url http://panel:50052 --api-key 'replace-with-a-long-random-key'
```

Startup validates the bind arguments, required API key, creates the volume/runtime directories, checks that the Docker CLI exists, runs `docker info`, and verifies access to the Docker daemon. It exits before opening listeners if Docker is missing or inaccessible. Every incoming gRPC call requires `authorization: Bearer <api-key>` metadata matching `--api-key`. The Panel URL is used lazily for every server/template/SFTP lookup and event report.

See [`API_SPEC.md`](API_SPEC.md) for the complete architecture and API contract.

SFTP usernames use the unambiguous form `<server_uuid>:<username>`. Passwords are verified locally against the bcrypt hash returned by `GetServerConfig`; sessions are jailed to that server volume and read-only users cannot mutate files.

## Implemented behavior

- `PowerAction`: Panel-backed image, command, env, ports, memory/swap/CPU/PID/IO limits, soft pre-start disk-limit check including external backups, volume setup, image pull, stale-container removal, stdin/TTY, stop command, timeout, kill, and event reporting.
- Docker event loop: reports stopped/crashed/OOM events, removes exited containers, and auto-restarts from freshly pulled Panel config when enabled.
- `RunTemplate`: Panel-backed image/script/entrypoint/env/memory, optional wipe, root ephemeral install container, streamed logs, cleanup, and ownership repair.
- `AttachConsole`: Docker live attach with stdin, stdout/stderr, and TTY resize messages.
- `StreamStats`: live Docker cgroup CPU, memory, network, and state frames.
- Filesystem RPCs: jailed metadata, list, mkdir, atomic move, recursive copy, delete, streamed binary reads/writes, permissions, and ownership.
- Archives: zip, tar, tar.gz, and tar.zst creation/extraction with archive path escape validation.
- Host stats: memory, disk, CPU core count, and daemon version.
- SFTP: password authentication, volume jail, read/write handles, directory handles, stat/lstat, mkdir/rmdir, rename, remove, and read-only enforcement.

The node does not maintain a database or server/template configuration files. The only runtime state is the SSH host key generated by Russh for the process lifetime; persistent host-key storage should be added if stable host identity across restarts is required.
